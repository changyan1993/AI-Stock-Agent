## 2026-03-14 V1 基线建立

### 第一阶段：初始回测 & Agent-3 参数优化

**起因**: 三个 Agent 初始回测，Agent-3 亏损严重

| Agent | 初始收益 | 初始胜率 |
|-------|---------|---------|
| Agent-1 | +$85.11 (+4.26%) | 68.5% |
| Agent-2 | +$38.61 (+1.93%) | 83.3% |
| Agent-3 | **-$66.90 (-3.35%)** | 46.1% |

**Agent-3 问题诊断**: 180 笔交易中 95 次止损，-4% 止损在高波动股上太窄，频繁被洗出

**尝试 1 — 收紧评分 + 放宽止损**: 评分逻辑加大惩罚，止损放宽到 -6%
- 结果: 更差 (-7.34%)，止损放宽让每笔亏损更大

**尝试 2 — 严格趋势确认**: 空头排列/RSI 弱势/MACD 负直接返回 -5 拒绝
- 结果: 更差 (-11.99%)，过滤掉了能赚钱的交易

**尝试 3 — 双向策略（趋势追涨 + 超跌反弹）**:
- 结果: 仍然亏损 (-9.73%)

**最终方案 — 网格搜索 3600 种参数组合**:
- 发现: 所有 Top 10 组合都是 **止损 -3% + 止盈 8%**
- 核心洞察: "快止损、慢止盈" — 止损收紧到 -3%，止盈放宽到 +8%
- 结果: Agent-3 从 -$66.90 翻转为 **+$69.05**

**关键经验**: 问题不在评分逻辑，而在收益风险结构。1:1 止损止盈改为 1:2.67 后，虽然胜率从 46% 降到 32%，但盈亏比 2.71 足以覆盖。

### 第二阶段：三步一致性校准

**目标**: 确保 backtest.py / analyze.js / CLAUDE.md 三处逻辑一致

#### Step 1: 出场逻辑统一
- **改动**: Agent-3 analyze.js 从 ATR 动态止损改为固定 -3%/+8%
- **文件**: stock-agent-3/analyze.js (line 628-630)
- **验证**: HOOD $73.39 → stop $71.19 (×0.97) ✓, TP $79.26 (×1.08) ✓

#### Step 2: 日内过滤验证
- **测试**: 把 dp>1%, c>o, day_position>0.6, market_score 加入回测
- **结果**: Agent-3 从 +$69 变成 -$52（负贡献）
- **原因**: 日线收盘数据无法模拟 10 分钟级盘中强势判断，硬映射导致入场偏晚
- **决定**: 日内过滤仅保留在 live 层，不纳入日线回测。待 10 分钟级回测再验证
- **代码**: backtest.py 中添加注释说明原因

#### Step 3: 大盘因子（SPY/QQQ/VIX）
- **实现**: 下载大盘历史数据，按 analyze.js 相同逻辑计算评分
- **初始测试（三个 Agent 统一加分）**:
  - Agent-1: +$85 → **+$94** (更好)
  - Agent-2: +$38 → **-$5** (变差)
  - Agent-3: +$69 → **-$3** (变差)
- **原因**: 大盘评分对动量策略是正贡献（顺势放大），对超卖反弹和激进追涨是负贡献（放宽了入场门槛）
- **决定**: 按策略类型分别处理 — Agent-1 保留，Agent-2/3 不加分
- **代码变更**:
  - backtest.py: `if market_data is not None and agent_id == 1:`
  - stock-agent-2/analyze.js: 注释掉 `score += marketData.score`
  - stock-agent-3/analyze.js: 注释掉 `score += marketData.score`

**关键经验**: 大盘评分不是通用 alpha，不同策略类型需要不同的市场因子使用方式。后续 Agent-2/3 如需市场因子，应改为 regime gate / 过滤条件。

### 第三阶段：Agent-2/3 含大盘评分口径参数重优化

**背景**: 守护任务在含大盘评分口径下对 Agent-2/3 重新网格搜索

**结果**: 3 轮迭代后 Agent-2 (-0.27%) 和 Agent-3 (-0.15%) 仍未转正
- 守护任务最终状态: NEEDS_MANUAL_REVIEW

**根因分析**: 统一大盘加分对 Agent-2/3 是负贡献，在同一套数据上反复调参无法解决因子设计问题

**决定**: 回退到按策略类型分别处理大盘因子的方案
- Agent-2/3 恢复到不含大盘评分时的最优参数
- 大盘评分仅 Agent-1 使用

**教训**: 多轮迭代在同一套 OOS 数据上调参会让验证失去意义（用户反馈记录在 memory）

### 第六阶段：执行层优化

#### 6a. Friction 模型
- 滑点 0.05% per trade（买高卖低），零佣金
- 每次往返约 0.1% 摩擦
- 影响: Agent-3 交易频率最高（94笔/6月），受影响最大

#### 6b. Agent-2 Time Stop
- 持仓超 15 天强制平仓
- 目的: 截断 CLF -$29 这类尾部亏损
- 实现: backtest.py + CLAUDE.md cron prompt

#### 6c. Agent-3 Regime Gate (初始版本，后在 6.5 阶段简化)
- market_score ≤ -2: 禁止买入
- market_score = -1: 只允许已有持仓管理，不开新仓
- market_score ≥ 0: 正常交易
- 实现: backtest.py + CLAUDE.md cron prompt
- **注**: 后在第 6.5 阶段简化为 kill-switch-only（移除 -1 限制）

#### 6d. 指标扩充
- expectancy = (wr × avg_win + (1-wr) × avg_loss) / |avg_loss|
- calmar_ratio = 年化收益 / |最大回撤|
- monthly_consistency = 盈利月数 / 总月数

### 第6.5阶段：Agent-3 Regime Gate 简化

**变更**: 从完整三级 regime gate 简化为 kill-switch-only
- **旧规则**: <= -2 禁止买入, == -1 最多1持仓, >= 0 正常
- **新规则**: <= -2 禁止买入, > -2 正常交易（移除 -1 限制）
- **原因**: -1 限制在回测中过度过滤，减少了有效交易机会
- **结果**: Agent-3 从 +$27.38 (+1.37%) 改善至 +$29.97 (+1.50%)，Sharpe 0.51→0.55

### V1.1 冻结决策 (2026-03-14)

**状态**: V1.1 FROZEN — 不再修改任何参数

**最终结果 (含 friction)**:
| Agent | P&L | WR | DD | Sharpe | Expectancy | Consistency |
|-------|-----|----|----|--------|------------|-------------|
| Agent-1 | +$92.99 (+4.65%) | 69.1% | -2.95% | 2.27 | 0.186 | 71.4% |
| Agent-2 | +$35.28 (+1.76%) | 71.4% | -1.52% | 0.87 | 0.167 | 57.1% |
| Agent-3 | +$29.97 (+1.50%) | 29.1% | -3.42% | 0.55 | 0.085 | 71.4% |

**Holdout**: ALL VALIDATED

**信任等级**:
- Agent-1: Primary (主观察对象) — 全窗口稳定正收益
- Agent-2: Stable supplement (稳健补充) — 低频稳健但样本少
- Agent-3: Experimental supplement (实验型补充) — 低胜率高盈亏比，需观察

**Paper Trading 计划 (2-4 周)**:
- 三个 Agent 同时纸上交易
- 跟踪指标: 信号数、成交率、SL/TP 比、持仓天数、live vs backtest 偏差
- Agent-1 为主要观察对象

**熔断规则**:
- 预警: 单周回撤 <= -4% → 加强监控，不自动暂停
- 熔断: 前两周累计回撤 <= -5% → 暂停开新仓，已有持仓正常出场
- 复核: 单笔异常? regime 突变? 执行偏差? → 恢复 / 降权 / 转 V1.2 research

**Agent-2 样本量触发器**:
- 4 周交易 < 5 笔 → 触发 V1.2 研究分支
- 研究顺序: ①降 buy_threshold 6→5 ②扩充股票池
- 不在 V1.1 baseline 上直接改，走独立验证流程

**Agent-2 信任等级下调**:
- V1.1 修正后真实基线: +$7.80 (+0.39%)，从"稳健补充"降为"待验证补充"
- 原因: time stop 口径修正（15日历天→21日历天≈15交易天）后暴露 CLF 尾部亏损
- 之前 +$35.28 有部分来自实现偏差（10交易天 time stop 恰好救了一笔）
- 教训: 参数语义必须明确（交易日 vs 日历天），否则基线会建立在已知错误上
